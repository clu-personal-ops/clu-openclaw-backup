- User was instructed to create an MCP token; awaiting token from user to configure server with `--header "Authorization=Bearer <token>"` approach.

## Qwen3.6 35B Tool-Calling/Session Failure Diagnosis (2026-11-01)

- **Model:** `qwen/qwen3.6-35b-a3b` via LM Studio (port 1234), OpenClaw 2026.10.8.
- **Root cause:** LM Studio's Qwen3.6 always returns `reasoning_content` regardless of `thinking.type: "disabled"` setting. Reasoning consumes 80-97% of output token budget.
- **LM Studio behavior verified via direct API:**
  - Default `max_tokens ~90`: 86 reasoning tokens, 4 content tokens → `finish_reason: "length"` (truncated/incomplete)
  - With `max_tokens=50`: 49 reasoning, 0 content → `finish_reason: "length"`
  - With `max_tokens=500`: 404 reasoning, 48 content → `finish_reason: "stop"` (truncated content)
  - With `thinking: {"type":"disabled"}`: 134 reasoning, 6 content → reasoning cannot be disabled
  - With tools defined + `max_tokens=500`: 82 reasoning, 27 content → tool calls work (when tokens remain)
- **Config gaps:** No `maxTokens` or `contextWindow` in provider config for LM Studio endpoint (`http://127.0.0.1:1234/v1`, api: `openai-responses`). Model override for `qwen/qwen3.6-35b-a3b` is `{}` (empty). Agent defaults to `thinking: "medium"`.
- **Failure chain:** `thinking: "medium"` → LM Studio always returns `reasoning_content` → reasoning consumes 80-97% of ~90 default max_tokens → 4-8 tokens for actual content/tool calls → `finish_reason: "length"` or silent failure → compaction drops prompt cache (49k→18k, 84k→49k), making it worse.
- **Recommended fix:** Add `params: { thinking: "off" }` to the model override for `qwen/qwen3.6-35b-a3b` in `openclaw.json`. This prevents reasoning from consuming the token budget, freeing it for content and tool calls.
- **Full diagnosis:** `memory/diagnosis-qwen3.6-tool-failure-2026-11-01.md`
